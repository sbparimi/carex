# Knowledge check — Lesson 4.1: Build a traceable test-planning contract

Choose the single best answer.

1. **What makes a test scenario traceable?**
   - A. It links to a requirement and the relevant API contract/operation
   - B. It has a descriptive name only
   - C. It was generated by Agent Mode
   - D. It returns HTTP 200

2. **The OpenAPI contract does not define an error response for cancellation at the 24-hour boundary. What should the plan contain?**
   - A. An invented 400 response
   - B. An open question requiring contract/implementation verification
   - C. A passing assertion with no body check
   - D. No scenario

3. **Which output is most useful for downstream collection design?**
   - A. Free-form paragraph
   - B. Unstructured list of endpoints
   - C. Scenario IDs, preconditions, request mapping, expected business outcome and evidence references
   - D. Only model confidence

## Answer key and explanations
1. **A.** A traceable scenario carries provenance from requirement to API operation.

2. **B.** Unknown response details must remain explicit, not fabricated.

3. **C.** Structured traceable fields enable review and implementation.
