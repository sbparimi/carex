# Lesson 1.4 — Predict the failure: where autonomy becomes unsafe

**Section:** 01 — Agentic SDLC and API Quality Engineering  
**Learner outcome:** Identify unsafe Agent Mode actions, prompt-injection risks, unsupported API assumptions and missing approval boundaries in a CareX change workflow.

## Seven-part lesson
1. **Opening:** Show an untrusted change description that attempts to redirect the agent and request broad access.
2. **Concept:** Explain prompt injection, over-permission, unsafe writes, secret exposure and false confidence.
3. **Why:** Connect these risks to customer data, collection integrity and release governance.
4. **Demo:** Ask Agent Mode to analyse the untrusted change while preserving explicit task boundaries; inspect its proposed actions.
5. **Build:** Complete the permission inventory and threat review using the supplied fixtures.
6. **Verify:** Check that unsupported instructions are treated as data, unsafe actions are rejected and human approval remains explicit.
7. **Recap:** Carry forward a threat checklist for all later Postman Agent Mode exercises.
