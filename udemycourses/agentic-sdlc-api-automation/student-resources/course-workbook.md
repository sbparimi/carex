# Agentic SDLC for API Automation — Student Workbook

**Learner edition:** Draft 0.1  
**Project:** CareX appointment-booking API  
**Use:** Keep this workbook as the course learning log. Complete the checkpoint after each lesson.

## How to use this workbook

- Download the lesson files listed in each lesson's student download index.
- Attempt the exercise before opening any completed solution.
- Record commands, run identifiers and observed results. Never record secrets.
- Compare your result with the expected outcome, not only with the instructor's screen.
- Keep each section's checkpoint; later sections build on earlier work.

## Course learning path

| Section | Learner outcome | Evidence to retain |
|---|---|---|
| 1. Agentic SDLC and API Quality Engineering | Distinguish agent reasoning, deterministic execution and human authority | Responsibility map and architecture notes |
| 2. Business Rules, Requirements and Change Intelligence | Convert a business change into traceable rules and impacted API journeys | Requirement record and impact map |
| 3. Agent Orchestration Architecture | Design bounded agent hand-offs with validated contracts | Workflow definition and schema checks |
| 4. Test Planning and Impact Analysis Agents | Produce reviewed, risk-based API scenarios | Traceable test plan |
| 5. Postman Collection Workflows | Implement and verify API business journeys | Postman collection and run results |
| 6. Postman CLI, Newman and GitHub Actions | Execute API regression in a controlled CI workflow | Pipeline run and reports |
| 7. Failure Diagnosis and Release Governance | Diagnose failures from evidence and apply release policy | Failure analysis and gate decision |
| 8. CareX End-to-End Capstone | Deliver a traceable change-to-release workflow | Capstone submission and evidence bundle |

## Learner evidence log

For each practical lesson, record:
- Lesson ID and resource version
- Starting checkpoint
- Commands or UI actions performed
- Test/run identifier
- Expected result
- Actual result
- Diagnosis if the result differs
- Final verification

## Safety

Use only the synthetic course environment. Never point write-enabled exercises at production. Do not commit tokens, passwords, database URLs or personal data.
