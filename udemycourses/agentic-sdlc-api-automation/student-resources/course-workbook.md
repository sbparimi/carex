# Agentic SDLC for API Automation — Student Workbook

**Learner edition:** Draft 0.2  
**Project:** CareX appointment-booking API  
**Primary workflow:** Postman Agent Mode → reviewed Postman collection → Postman CLI → GitHub Actions.

## How to use this workbook
- Download the lesson files listed in each lesson's student download index.
- Attempt the exercise before opening any completed solution.
- Use Postman Agent Mode prompts to analyse requirements and generate/update collection requests or test scripts.
- Review every generated change against the business requirement and CareX OpenAPI contract.
- Record run identifiers, collection commits and observed results. Never record secrets.
- Compare your result with expected outcomes, not only with the instructor's screen.
- Keep each section's checkpoint; later sections build on earlier work.

## Course learning path

| Section | Learner outcome | Evidence to retain |
|---|---|---|
| 1. Agentic SDLC and API Quality Engineering | Distinguish Postman Agent Mode reasoning, deterministic Postman verification and human authority | Responsibility map and governance lab result |
| 2. Business Rules, Requirements and Change Intelligence | Use Agent Mode to extract source-linked rules and impacted API journeys | Reviewed requirement record and impact map |
| 3. Agent Orchestration Architecture | Design bounded Agent Mode tasks, hand-offs and structured proposals | Prompt cards, workflow map and validated JSON |
| 4. Test Planning and Impact Analysis Agents | Generate and review risk-based API scenarios | Traceable test plan and coverage review |
| 5. Postman Collection Workflows | Use Agent Mode to create/update and verify API business journeys | Reviewed Postman collection and run results |
| 6. Postman CLI and GitHub Actions | Execute reviewed collections in a controlled CI workflow | CLI run, CI workflow and reports |
| 7. Failure Diagnosis and Release Governance | Diagnose failures from evidence and apply deterministic release policy | Failure analysis and gate decision |
| 8. CareX End-to-End Capstone | Deliver a traceable change-to-release workflow | Capstone submission and evidence bundle |

## Learner evidence log
For each practical lesson, record lesson ID/resource version, starting checkpoint, Agent Mode prompt and output where relevant, collection revision, environment name (not secrets), run ID, expected result, actual result, diagnosis and final verification.

## Safety
Use only the synthetic course environment. Never point write-enabled exercises at production. Do not commit tokens, passwords, database URLs or personal data. Agent Mode cannot approve release or override mandatory gates.
