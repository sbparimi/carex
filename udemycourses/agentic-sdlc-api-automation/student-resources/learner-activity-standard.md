# Learner activity standard

Every lesson must require an observable learner action. Every section integrates the skills taught; the course remains one progressive CareX project.

## Mandatory per-lesson package
1. Video using Opening, Concept, Why, Demo, Build, Verify, Recap.
2. Three-to-five-question knowledge check with one defensible answer and explanations.
3. Practical assignment or meaningful decision exercise.
4. Relevant code/configuration snippets; structured artefacts may replace code in conceptual lessons.
5. Starter checkpoint and exact setup instructions.
6. Expected outputs with interpretation guidance.
7. Completed reference solution tested independently and separated from starter.
8. GitHub link pinned to a stable commit or tag.
9. Troubleshooting note and at least one failure/edge case.
10. Completion evidence and connection to the next lesson.

## Activity by lesson type
- Conceptual: scenario quiz, decision exercise, traceability worksheet or architecture review.
- Technical: runnable lab, starter, positive and negative cases, expected output and tested solution.
- Integration: multi-step assignment combining prior artefacts.
- Capstone: end-to-end change request, evidence pack, rubric and controlled release recommendation.

Do not force code into conceptual lessons. Do not let technical lessons end with only a quiz.

## Udemy implementation
Use native Udemy quizzes for knowledge checks; coding exercises only where supported and meaningful; assignments for larger applied work. Attach lesson resource ZIPs to relevant lectures and link the versioned GitHub checkpoint. Provide downloadable ZIP alternatives for learners who do not use GitHub. Test all attachments and links as a learner.

## Release gate
A lesson is not ready until applicable components exist, repository checkpoints are pinned, files open, commands run from a clean environment, and expected results have retained evidence. Templates and README files are not proof of a working lab.
